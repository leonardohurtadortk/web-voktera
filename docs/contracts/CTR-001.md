# CTR-001 — Estándar de Diseño Responsive y UX

## Descripción
Define el estándar de diseño responsive y experiencia de usuario para el sitio `voktera.online` y sus futuras landings (verticales y zonas). Garantiza comportamiento consistente en móvil, tablet y escritorio. Documenta el estado **real** del CSS actual (desktop-first) y fija el estándar **deseado** (mobile-first) como objetivo de migración.

## Entradas
- Hoja de estilos compartida `voktera.online/styles.css` (774 líneas), enlazada con `<link rel="stylesheet" href="../styles.css">` en las 15 páginas. No hay CSS embebido en `<style>` (ver CTR-002, checklist obligatorio).
- Variables de diseño: `--bg #F2EFE9`, `--bg-soft #EAE5DB`, `--ink #1F1B16`, `--ink-soft #5A5249`, `--accent #D9651B`, `--accent-2 #4A6B4D`, `--line #D8D2C5`, `--card #FFFFFF`.
- Tipografías: Archivo Expanded (display), Archivo (body), JetBrains Mono (mono).

## Salidas
- Layout adaptable en los breakpoints definidos.
- Comportamiento consistente de navegación, hero, servicios, pasos, zonas y contacto.

## Excepciones
- `prefers-reduced-motion`: desactiva animaciones (`pulse`, `rise`) en hero y toolbox.
- Dispositivos sin soporte de `backdrop-filter`: el nav sticky degrada a fondo sólido.

## API
### Breakpoints reales (estado actual — mobile-first, desde T-014)
El CSS base describe el móvil; las mejoras progresivas usan `min-width`:

| Breakpoint | Efecto (mobile-first) |
|---|---|
| `min-width: 600px` | `.toolbox-grid` → 2 columnas; `.contact` padding amplio; `.wa-float` 60px; `.blog-content` 1.05rem |
| `min-width: 700px` | `.service-row` → `200px 1fr` |
| `min-width: 800px` | `.steps` → 3 columnas |
| `min-width: 900px` | `.hero-grid` → 2 columnas; nav horizontal (burger oculto); dropdown en hover/focus/open |

Migración ejecutada bajo T-014 (hijas T-036 a T-042). **Todas las media queries de `styles.css` usan `min-width`; no queda ninguna `@media (max-width: ...)`.**

### Estándar vigente (mobile-first)
- Base CSS para móvil; mejoras progresivas con `min-width` en los umbrales (600, 700, 800, 900).
- Targets táctiles ≥ 44px; contraste AA; tipografía fluida con `clamp()` (ya usada en `h1` y `.section-title`).
- Las futuras verticales (MOD-003..006) y zonas (`cerrajero-<ciudad>/`) heredan este estándar.

### Estándar móvil (T-028 + T-036 + T-049)
- **Menú hamburguesa CSS-only** como base móvil: `input#nav-toggle.nav-toggle` + `label.nav-burger` (3 span) dentro de `.nav-inner`, seguidos de `<nav class="nav-links">`. El panel se despliega con `.nav-toggle:checked ~ .nav-links` (position:absolute bajo el header, z-index 1000, fondo `--card`). En `min-width: 900px` el burger se oculta y el nav pasa a horizontal.
- **Dropdown de Servicios**: en `min-width: 900px` abre con `:hover`, `:focus-within` y con la clase de estado `.open` (T-049, `nav.js`: toggle por clic, cierre por clic-fuera y Escape, `aria-expanded`). Un puente `::after` de 10px evita que el panel parpadee al mover el mouse del toggle al panel.
- **Botón flotante `.wa-float`**: base móvil 56x56px, `bottom:32px`, `right:16px`, `z-index:1000`; `min-width: 600px` → 60x60px, `right:24px`, `z-index:100`. El footer lleva `padding-bottom:96px` para no quedar tapado.
- **Hero**: `.hero-media` base 16/10, `min-width: 900px` → 4/3; `.hero-gallery` base 1 columna 16/10, `min-width: 900px` → 2 columnas 3/4. `.hero-media .hero-img` usa `object-fit: cover` + `object-position: center`; las fotos verticales se recortan hasta que se reemplacen por horizontales (T-048).
- **Cobertura**: las 15 páginas (home, 4 verticales, 7 locales, 3 blog) usan el mismo markup y la misma clase; el estilo vive solo en `styles.css`.
- Cualquier página nueva debe heredar estos patrones (ver CTR-002).

## Restricciones
- **No cambiar la paleta ni las variables de diseño** sin consenso (afecta identidad de marca).
- **Deuda técnica en curso:** la migración de `max-width` (desktop-first) a `min-width` (mobile-first) se ejecuta en `voktera.online/styles.css` bajo T-014 y sus 7 tareas hijas atómicas (T-036 a T-042). Las tareas T-002, T-004 y T-010 están archivadas; la advertencia anterior sobre ellas ya no aplica.
- Los breakpoints pueden añadirse, no eliminarse sin consenso.
